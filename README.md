# SingleFile Companion (for Edge)

A small Go native-messaging host for [SingleFile](https://www.getsinglefile.com/), inspired by [Literary Machines' blog post "Lightweight web archiving with SingleFile"](https://literarymachin.es/singlefile/). When SingleFile sends a saved page, the companion writes the HTML to a configured archive directory, appends metadata to a JSON Lines index, and rebuilds a table-based HTML index.

## Requirements

- Windows 10 or later and Microsoft Edge
- Docker Desktop with Linux containers enabled (Go does not need to be installed on Windows)
- The SingleFile Edge extension

## Build

From the project directory, run in PowerShell:

```powershell
docker build --output "type=local,dest=dist" .
```

The Docker build runs the Go tests and cross-compiles `dist\singlefile_companion.exe` for Windows/amd64. Keep the executable in a stable directory; Edge's native-host registration points to its full path.

## Configure the archive

Copy the example config beside the executable and edit it:

```powershell
Copy-Item .\sfc.yml.example .\dist\sfc.yml
notepad .\dist\sfc.yml
```

Set `archive_dir` to the archive directory. Relative paths in the config are resolved from the executable's directory. The optional `index_jsonl` and `index_html` values are filenames created inside the archive directory; their defaults are `index.jsonl` and `index.html`.

For example:

```yaml
archive_dir: "C:\\Users\\YOUR_NAME\\WebArchives"
index_jsonl: "index.jsonl"
index_html: "index.html"
```

Each successful save creates the page file, appends one record (`date`, `url`, `file`, `title`) to `index.jsonl`, and refreshes `index.html`. The HTML index and saved pages are ordinary files.

## Register the native-messaging host in Edge

1. In Edge, open `edge://extensions`, enable **Developer mode**, and note the ID shown for SingleFile.
2. In PowerShell, run the following from the project directory, replacing the extension ID:

   ```powershell
   $exe = (Resolve-Path .\dist\singlefile_companion.exe).Path
   $extensionId = "PASTE_SINGLEFILE_EXTENSION_ID_HERE"
   $manifestPath = Join-Path (Split-Path $exe) "singlefile_companion.json"

   @{
       name = "singlefile_companion"
       description = "SingleFile Go Companion"
       path = $exe
       type = "stdio"
       allowed_origins = @("chrome-extension://$extensionId/")
   } | ConvertTo-Json -Depth 4 | Set-Content -Encoding ascii $manifestPath

   $registryKey = "HKCU:\Software\Microsoft\Edge\NativeMessagingHosts\singlefile_companion"
   New-Item -Path $registryKey -Force | Out-Null
   Set-Item -Path $registryKey -Value $manifestPath
   ```

   The manifest and registry entry use the host name `singlefile_companion`, which is the name SingleFile uses for its companion host. The manifest's origin must match the extension ID exactly.
3. If SingleFile was already open, restart Edge after registering the host.
4. In SingleFile's settings, choose **Destination → Save with SingleFile Companion**. If prompted for permission to exchange messages with other programs, allow it.

To unregister the host later:

```powershell
Remove-Item "HKCU:\Software\Microsoft\Edge\NativeMessagingHosts\singlefile_companion" -Recurse
```

## Suggested SingleFile settings

These settings are optional, but align with the archive workflow:

- **File name → Template**: `{url-href-digest-sha-1}.{time-ms}.{filename-extension}`. The opaque, unique name is mapped to the original URL and title by the index.
- **HTML content → Save original URLs of embedded resources**: enabled.
- **Destination → Save with SingleFile Companion**: enabled.
- Infobar options are a matter of preference; for example, use `{url-href} ({date-iso})` and include it in the saved page.

## Native messaging protocol

Edge launches the registered executable and exchanges UTF-8 JSON messages over stdin/stdout. Each message is prefixed by a 4-byte little-endian length. This host accepts SingleFile's `save` request with `pageData.filename`, `pageData.url`, and `pageData.content`. Successful saves produce no response; errors are returned as a framed JSON object containing an `error` field. Messages larger than 1 GiB are rejected.
